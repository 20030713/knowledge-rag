# 宝塔生产部署说明

本说明适用于约 2 GB 内存的阿里云 Linux 服务器。生产编排文件为 `docker-compose.prod.yml`，只把前端端口绑定到服务器回环地址，MySQL、Redis、pgvector 和后端不会直接暴露到公网。

## 1. 上传目录

在宝塔文件管理中创建：

```text
/www/wwwroot/knowledge-rag
```

把项目代码上传并解压到这个目录。不要上传本地 `.env`、`.git`、`target`、`frontend/node_modules`、`frontend/dist` 和 `uploads`。

## 2. 创建生产环境变量

在宝塔终端执行：

```bash
cd /www/wwwroot/knowledge-rag
cp .env.production.example .env
chmod 600 .env
```

生成随机密码：

```bash
openssl rand -base64 36
openssl rand -base64 36
openssl rand -base64 36
openssl rand -base64 48
```

将四次输出分别填入：

```text
MYSQL_ROOT_PASSWORD
MYSQL_PASSWORD
PGVECTOR_PASSWORD
JWT_SECRET
```

再填写新生成的 DeepSeek 和百炼 API Key。不要继续使用已经公开过的旧 Key。

## 3. 校验配置

```bash
docker compose --env-file .env -f docker-compose.prod.yml config --quiet
```

命令没有输出即表示配置语法通过。

## 4. 低内存服务器分步构建

不要同时构建两个镜像，按顺序执行：

```bash
docker compose --env-file .env -f docker-compose.prod.yml build backend
docker compose --env-file .env -f docker-compose.prod.yml build frontend
docker compose --env-file .env -f docker-compose.prod.yml up -d
```

首次构建需要下载 Maven、Node 和基础镜像，耗时取决于网络。如果出现 `Killed` 或退出码 `137`，说明内存不足，应将 Swap 增加到 2 GB 后重试。

## 5. 查看启动状态

```bash
docker compose --env-file .env -f docker-compose.prod.yml ps
docker compose --env-file .env -f docker-compose.prod.yml logs --tail=200 backend
```

本机验证：

```bash
curl http://127.0.0.1:15173/api/health
```

健康接口返回成功后，再配置宝塔站点。

## 6. 宝塔反向代理

1. 在宝塔“网站”中添加域名，例如 `rag.example.com`。
2. PHP 版本选择“纯静态”。
3. 进入站点设置的“反向代理”。
4. 代理名称填写 `knowledge-rag`。
5. 目标 URL 填写 `http://127.0.0.1:15173`。
6. 发送域名填写 `$host`，内容替换留空。

在该反向代理的自定义配置中确认包含：

```nginx
proxy_http_version 1.1;
proxy_buffering off;
proxy_cache off;
proxy_read_timeout 3600s;
proxy_send_timeout 3600s;
client_max_body_size 25m;
```

`proxy_buffering off` 用于避免 SSE 流式回答被宝塔 Nginx 缓冲成一次性返回。

## 7. 域名和 HTTPS

将域名 A 记录解析到服务器公网 IP。解析生效后，在宝塔站点的“SSL”页面申请 Let's Encrypt 证书，然后开启强制 HTTPS。

阿里云轻量服务器和宝塔防火墙只需开放 `80`、`443`；SSH 和宝塔面板端口建议仅允许自己的公网 IP。不要开放 `15173`、`8080`、`3306`、`3307`、`5432`、`6379`。

## 8. 更新系统

上传新代码后执行：

```bash
cd /www/wwwroot/knowledge-rag
docker compose --env-file .env -f docker-compose.prod.yml build backend
docker compose --env-file .env -f docker-compose.prod.yml build frontend
docker compose --env-file .env -f docker-compose.prod.yml up -d
```

## 9. 停止和备份

停止但保留数据：

```bash
docker compose --env-file .env -f docker-compose.prod.yml down
```

不要执行 `down -v`，它会删除 MySQL、Redis、pgvector 和上传文件对应的数据卷。

升级或改配置前，可以备份数据库：

```bash
docker exec knowledge-rag-mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --databases knowledge_rag' > knowledge_rag_backup.sql
```
