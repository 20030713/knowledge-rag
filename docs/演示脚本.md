# 项目演示脚本

这份脚本用于面试或录屏演示。建议演示控制在 5-8 分钟，先跑核心链路，再讲技术亮点。

## 1. 演示前准备

### 推荐：Docker 一键启动

```bash
docker compose up -d --build
```

启动完成后访问：

```text
前端：http://localhost:5173
后端：http://localhost:8080/api/health
接口文档：http://localhost:8080/doc.html
```

### 可选：本地开发启动

如果需要本地开发调试，也可以分别启动依赖、后端和前端。

启动依赖：

```bash
docker compose up -d mysql redis
```

启动后端：

```bash
mvn spring-boot:run
```

启动前端：

```bash
cd frontend
npm install
npm run dev
```

默认前端地址：

```text
http://localhost:5173
```

后端接口文档：

```text
http://localhost:8080/doc.html
```

## 2. 演示路径

README 中已经准备了四张界面展示图：

```text
docs/images/login-preview.svg
docs/images/workspace-preview.svg
docs/images/rag-preview.svg
docs/images/dashboard-preview.svg
```

这些图用于 README 展示和面试前快速说明页面结构。Docker 全栈跑通后，也可以用真实浏览器截图替换这些 SVG 展示图。

### 第一步：登录或注册

讲解点：

- 系统使用 JWT 登录鉴权
- 前端会保存 token
- 后端通过拦截器解析当前用户

演示动作：

1. 打开前端页面
2. 输入账号密码
3. 点击进入工作台

### 第二步：创建知识库

讲解点：

- 知识库是权限边界
- 所有文档、chunk、问答记录都绑定 `user_id` 和 `kb_id`
- 问答时只检索当前知识库

演示动作：

1. 点击“新建知识库”
2. 修改名称，例如“Java 实习项目资料库”
3. 保存

### 第三步：上传并解析文档

讲解点：

- 支持 PDF、Word、Markdown、TXT
- 上传后只保存文件和元数据
- 解析是异步任务
- Redis 分布式锁防止重复解析

演示动作：

1. 上传一份项目文档或 Markdown 文件
2. 点击“解析”
3. 观察状态变为 `PARSING`
4. 等待状态变为 `COMPLETED`
5. 查看 chunk 预览

### 第四步：查看任务中心

讲解点：

- 任务中心用于观察异步任务
- 可按状态筛选
- 失败任务支持重试
- 当前轻量版复用 `document` 状态字段

演示动作：

1. 切换到 RAG / 仪表盘页
2. 查看解析任务中心
3. 切换不同状态筛选

### 第五步：提问并查看引用

讲解点：

- 问答前会做 Redis 限流
- 先查 Redis 问答缓存
- 缓存未命中时进行本地向量检索
- 返回引用片段、来源文档和检索分数

演示问题示例：

```text
这个项目用了哪些 Redis 模块？
```

```text
文档解析为什么要异步处理？
```

```text
MySQL 和向量检索分别负责什么？
```

演示动作：

1. 切换到问答页
2. 输入问题
3. 查看回答
4. 展示引用来源
5. 展示 `final / vector / keyword` 分数

### 第六步：问答反馈

讲解点：

- 用户可以反馈回答是否有帮助
- 仪表盘统计反馈数量和质量
- 后续可用于 Prompt 调优和检索权重调优

演示动作：

1. 点击“有帮助”或“没帮助”
2. 查看历史记录中的反馈状态
3. 切换反馈筛选
4. 查看仪表盘反馈统计

### 第七步：删除知识库

讲解点：

- 删除知识库会级联清理文档、chunk、问答历史
- Redis 缓存和本地文件在事务提交后清理
- 避免留下孤儿数据

演示动作：

1. 点击删除知识库
2. 说明确认弹窗
3. 不一定真的删除演示数据，视情况决定

## 3. 讲解顺序建议

推荐顺序：

```text
登录 -> 知识库 -> 上传文档 -> 异步解析 -> chunk 预览 -> RAG 提问 -> 引用来源 -> 反馈 -> 仪表盘
```

不要一开始就讲所有技术细节。先让面试官看到系统能跑，再补充关键技术。

## 4. 演示时的核心话术

可以这样串起来：

```text
这个项目的核心链路是：用户上传私有文档，系统异步解析并切分成 chunk；问答时只在当前知识库内检索相关 chunk，返回答案和引用来源。为了让它更像真实后端系统，我做了 JWT 鉴权、Redis 限流、问答缓存、文档解析分布式锁、任务中心、失败重试和回答反馈闭环。
```

## 5. 如果现场出问题怎么说

### 文档解析失败

可以说：

```text
系统会把失败原因写入 document.error_msg，并在任务中心展示。失败次数会递增，超过 3 次后禁止继续重试，避免无效任务反复提交。
```

### Redis 没启动

可以说：

```text
当前本地演示环境对 Redis 做了降级处理。Redis 不可用时，限流、缓存和分布式锁会跳过，核心登录、上传、问答链路仍然可以运行。生产环境可以改成更严格的拒绝策略。
```

### 回答不够自然

可以说：

```text
当前版本重点先打通 RAG 后端链路，回答还是基于引用片段的模板化总结。后续会接入真实 ChatModel，让大模型基于召回片段生成更自然的回答。
```

### 向量检索效果一般

可以说：

```text
当前使用本地 Hashing Vectorizer，是为了不依赖外部模型先搭好向量检索架构。后续可以替换为真实 Embedding 模型和 Milvus / pgvector。
```
